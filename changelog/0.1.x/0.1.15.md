# 0.1.15 — 2026-07-10

## Fixed

- **`eurostat_query_dataset` / `eurostat_browse_themes` content[] parity** — `query_dataset`'s `format()` rendered only the first 200 observations behind a hardcoded cap while `structuredContent` carried up to 5,000; the cap and its "N more not shown" note are removed so both channels carry identical rows. `browse_themes`'s `format()` rendered `hasChildren` only when `true`; the `false` state now renders explicitly as "(no children)" ([#15](https://github.com/cyanheads/eurostat-mcp-server/issues/15)).
- **`eurostat_get_dimension_values` full time range + geo default** — every non-geo dimension was queried with `lastTimePeriod=1`, truncating `time` to its latest period; `getDimensionValues()` now probes a single period, pins every other dimension to its first value, and leaves `time` unfiltered to enumerate the complete range in one bounded call. `geo` without `geo_level` now defaults to `geoLevel=country` per the tool's documented default. Adds a declared `async_response` error variant (non-retryable) for dimension queries too large to bound this way ([#17](https://github.com/cyanheads/eurostat-mcp-server/issues/17)).
- **`eurostat_query_dataset` invalid-dimension error classification** — an invalid filter dimension (Eurostat HTTP 400, error id 150) bypassed the declared `invalid_dimension` contract and surfaced the raw `FetchHttpError` with the wrong JSON-RPC code (`-32602` instead of `-32007`). `fetchJson()`'s catch block now re-parses the captured error body for any non-2xx response and routes it through the existing classifier, so `invalid_dimension` and `not_found` are reachable on the live HTTP path, not just the 200-wrapped async-413 warning ([#18](https://github.com/cyanheads/eurostat-mcp-server/issues/18)).
