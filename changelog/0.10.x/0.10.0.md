# 0.10.0 — 2026-10-14

## Added

- **`eurostat_get_dimension_values` takes `filter`, `limit`, and `cursor`** ([#64](https://github.com/cyanheads/eurostat-mcp-server/issues/64)) — `filter` keeps values whose code and label contain every word given (case- and accent-blind, any order), with `matchCount` counting the matches; a page with more after it carries `truncated`, `nextCursor`, and a `notice`. A cursor bound to another `dataset_code`, `dimension`, `geo_level`, or `filter`, or resuming after a code no longer listed, fails as `invalid_cursor`; every binding but `geo_level` is checked before the dimension's structure is fetched. On a deployment with a dataframe canvas, `canvas_id` beside `cursor` fails as `conflicting_params`; without one, `canvas_id` is ignored and the page is served. A filter that matches nothing on a call that staged the list names the staged table.
- **Partial and stale catalogues are disclosed** ([#63](https://github.com/cyanheads/eurostat-mcp-server/issues/63)) — while the Comext dataflow list is unmerged, `eurostat_search_datasets` and `eurostat_browse_themes` (on `ext_go` and `icts`) carry `comextListMissing` and a `notice`, `no_match` hints name it, and `not_found` on a Comext folder or `DS-*` code says the list could not be loaded. A catalogue a failed TOC refresh could not replace carries `catalogueLoadedAt`, and a search `no_match` or browse `not_found` answered from it names that load time in its hint.
- **`eurostat_search_datasets` `no_match` names the blocking word** ([#69](https://github.com/cyanheads/eurostat-mcp-server/issues/69)) — for two or more distinct words, each word whose removal alone yields matches is listed with its count (`Without "rates": 7 matches.`), counted in one pass over the catalogue.
- **Upstream outages fail as retryable `upstream_fault`** ([#71](https://github.com/cyanheads/eurostat-mcp-server/issues/71)) — an HTTP 5xx or an unreachable host that outlasts the retries, on every tool that calls Eurostat, with an outage hint (HTTP 501 is not retryable); the `eurostat://dataset/{dataset_code}` resource fails with the same retryable `upstream_fault`, without a hint. `eurostat_download_dataset`, filtered or not, now retries its SDMX data request on an outage instead of failing on the first attempt, and `eurostat_search_datasets` and `eurostat_browse_themes` fail the same way when no catalogue has loaded yet.

## Changed

- **Breaking: `eurostat_query_dataset` rejects filter keys named like Eurostat API controls** (`lang`, `format`, `geoLevel`, `sinceTimePeriod`, `untilTimePeriod`, `lastTimePeriod`, any case) as `invalid_dimension` ([#62](https://github.com/cyanheads/eurostat-mcp-server/issues/62)). Some such calls used to return data; set the `lang`, `geo_level`, `since_period`, `until_period`, or `last_n_periods` input instead.
- **Breaking: `eurostat_get_dimension_values` no longer returns `shown` and `cap`** ([#64](https://github.com/cyanheads/eurostat-mcp-server/issues/64)). Long lists are paged within a 64,000-byte budget per response surface with `nextCursor`, instead of being cut at 2,000 values.
- **`eurostat_search_datasets` matches across spacing beside punctuation** ([#69](https://github.com/cyanheads/eurostat-mcp-server/issues/69)) — `Rev.2` finds `Rev. 2`, and `R&D`, `non-EU`, and `DS-045409` keep their punctuation. Search text is built once per catalogue snapshot.
- **Eurostat error labels in messages end in one period**, and server log lines no longer carry request URLs; fetches are labelled by endpoint.
- **`instructions`, tool descriptions, `README.md`, and `docs/design.md`** describe paging, outage and partial-catalogue behavior, and the new rejections.
- **`CLAUDE.md`/`AGENTS.md`** follow the 0.13.15 template, and the framework anti-pattern checks in `scripts/check-framework-antipatterns.ts` use POSIX character classes.
- **Framework** — `cyanheads/mcp-ts-core` ^0.13.11 → ^0.13.15: log records carry no request URLs, and `eurostat_dataframe_query` runs on a DuckDB canvas with external access off, with an SQL gate that refuses more functions and file references. Framework skills are synced to 0.13.15.

## Fixed

- **A blank or whitespace-only filter element is unset** ([#61](https://github.com/cyanheads/eurostat-mcp-server/issues/61)) — `[""]` accepts every value and `["", "DE"]` is `["DE"]` on `eurostat_query_dataset` and `eurostat_download_dataset`, in the request, the `geo`/`geo_level` check, `appliedFilters`/`appliedQuery`, and the too-large hint. A blank used to be sent upstream and echoed as applied.
- **A time filter beside a period input fails as `conflicting_params`** ([#70](https://github.com/cyanheads/eurostat-mcp-server/issues/70)) — `filters.time` or `filters.time_period` (any case) with `since_period`, `until_period`, or `last_n_periods` is refused before any request, and Eurostat's own "cannot be set at the same time" refusal is no longer reported as `invalid_period`.
- **Declared `canvas_not_found` and `missing_table` recoveries reach callers** ([#68](https://github.com/cyanheads/eurostat-mcp-server/issues/68)) on `eurostat_query_dataset`, `eurostat_download_dataset`, `eurostat_get_dimension_values`, `eurostat_dataframe_describe`, and `eurostat_dataframe_query`, in place of the canvas service's generic hints.
- **The canvas-off over-cap notice and truncation banner of `eurostat_query_dataset` name only filters and a period range** ([#65](https://github.com/cyanheads/eurostat-mcp-server/issues/65)); they used to route to `eurostat_download_dataset`, which keeps only its preview without a canvas.
