# 0.11.1 — 2026-10-31

## Changed

- **`since_period` / `until_period`** on `eurostat_query_dataset` and `eurostat_download_dataset`: a success names each period a bound falls inside, which Eurostat excludes because it keeps only periods wholly inside a range, and the bound that includes it. The download names only frequencies its TSV header shows. When both bounds cut one period, the query notice uses a plural form naming both. The descriptions state the rule in place of "mapped onto the dataset's own" ([#84](https://github.com/cyanheads/eurostat-mcp-server/issues/84)).
- **`content[]`** of both tools lists each dimension holding one value across the rows shown once above the rows; `urb_cpop1` at `preview_limit: 500` went from 43,856 to 13,016 bytes ([#86](https://github.com/cyanheads/eurostat-mcp-server/issues/86)).
- **`eurostat_get_dimension_values`** `no_results` for an empty `geo_level` offers only the levels the dataset's `geo` codes carry, and offers omitting `geo_level` only when `country` is among them ([#87](https://github.com/cyanheads/eurostat-mcp-server/issues/87)).
- **`eurostat_query_dataset`** `no_results` for a query that set `geo_level` names it as the likely cause when Eurostat's reply says nothing more, lists the dimensions of a dataset without `geo`, and recommends dropping `geo_level` ([#85](https://github.com/cyanheads/eurostat-mcp-server/issues/85)).
- **Recovery hints** that read the dataset structure do so under a fixed 5 s deadline across retries: the query's `no_results` and `async_response`, and the download's `extraction_too_big` when no filter has read it already. `async_response` and `extraction_too_big` hints previously read under `EUROSTAT_REQUEST_TIMEOUT_MS` ([#85](https://github.com/cyanheads/eurostat-mcp-server/issues/85)).
- **`skills/eurostat-guide`** 1.0 → 1.1.

## Fixed

- **One-day ranges** select that day: the query sends `time=<date>`, and the download requests the day and the next, dropping the later column before anything is counted or staged. Both used to return the whole series. The download's `appliedQuery.url` shows an `endPeriod` a day past `untilPeriod` ([#88](https://github.com/cyanheads/eurostat-mcp-server/issues/88)).
- **Rejected forms:** a one-day range whose day holds no published period, or on a dataset with no period that short, used to return the whole series and now fails. The query fails as `no_results`; the download fails as `invalid_dimension` (fault 150) or `no_results`, depending on Eurostat's reply ([#88](https://github.com/cyanheads/eurostat-mcp-server/issues/88)).
- **`eurostat_query_dataset` `no_results` for a range that selects no period** is diagnosed as outside the coverage, holding no whole period (naming the bound or bounds that select one), or holding no published period (pointing to `eurostat_get_dimension_values` with `dimension: "time"`). Previously every case read as outside the coverage. A `filters.time` that selects nothing, with no bounds set, keeps its outside-coverage message ([#84](https://github.com/cyanheads/eurostat-mcp-server/issues/84)).
- **Download fault 150** splits on `allowed: TIME_PERIOD: [<>]=`: a range that selects no period reports `invalid_dimension` with a range message that omits Eurostat's clause, and a filter value spelling that clause stays a filter fault. It previously read as a rejected filter value, with a range outside the coverage as the one alternative ([#84](https://github.com/cyanheads/eurostat-mcp-server/issues/84)).
