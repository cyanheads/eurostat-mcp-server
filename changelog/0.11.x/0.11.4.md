# 0.11.4 — 2026-11-14

## Added

- **`extraction_too_big`** on `eurostat_query_dataset`: Eurostat's other 413 refusals, non-retryable, with hints that name the dimensions left open ([#106](https://github.com/cyanheads/eurostat-mcp-server/issues/106)).
- **`lastUpdated`** on `eurostat_browse_themes` items (dd.mm.yyyy, as search reports it); folders carry none ([#111](https://github.com/cyanheads/eurostat-mcp-server/issues/111)).
- **Time-key hint** on `eurostat_download_dataset`: a `filters` key `time` or `time_period` (any case) gets advice to remove it and set `since_period`/`until_period`, quoting the range when every value is a period ([#109](https://github.com/cyanheads/eurostat-mcp-server/issues/109)).
- **`skills/eurostat-guide`** 1.2.0 → 1.3.0: "Find a dataset and its codes" and "Choose a period range" workflows ([#110](https://github.com/cyanheads/eurostat-mcp-server/issues/110)).

## Changed

- **`EUROSTAT_BULK_TIMEOUT_MS`** is the download's time budget counted from the call's start, default 120000 → 55000. It covers the structure read, attempts, backoff, body and staging; reached after rows have streamed it keeps them as a prefix with `budgetExceeded: true`, and before the first row the call fails as `retry_deadline_exceeded`. The dimension-value index's two background downloads keep a fixed 2 minutes ([#108](https://github.com/cyanheads/eurostat-mcp-server/issues/108)).
- **Behavior under the 55 s budget:** a plain-served download that took 55–61 s on 0.11.3 now returns a prefix with `budgetExceeded: true` (about 17–44 unfiltered datasets sit in that band), and an upstream outage the download rode out within 120 s now fails once the budget is spent. Raising `EUROSTAT_BULK_TIMEOUT_MS` restores both, for clients that wait past the 60 s request timeout MCP SDK clients default to.
- **`eurostat_query_dataset`** `async_response` is retryable and each call sends one request; `eurostat_download_dataset` `async_queued` is retryable, one request per call. Hints offer the repeat ([#106](https://github.com/cyanheads/eurostat-mcp-server/issues/106)).
- **`eurostat_download_dataset`** caches each dataset's dimension order beside its metadata for the hour, so a filtered download no longer re-reads the structure each call. A `filter_arity` refusal, or `invalid_dimension` other than a rejected period range, drops the cached order. A structure change inside the hour fails one filtered download before the repeat re-reads it ([#105](https://github.com/cyanheads/eurostat-mcp-server/issues/105)).
- **Tool and field descriptions** name no environment variable, request parameter, HTTP status or SDMX faultcode, and state each rule once on the field that defines it. Canvas-on description text 64,202 → 41,861 B; `tools/list` 81,757 → 59,469 B. A registration test holds the size budget ([#110](https://github.com/cyanheads/eurostat-mcp-server/issues/110)).
- **`eurostat_get_dimension_values`** decides the empty `country` default's `no_results` after staging, so `canvas_id` stages a NUTS-only dataset's `geo` list, with a notice routing to the `geo_level` that lists it ([#112](https://github.com/cyanheads/eurostat-mcp-server/issues/112)).
- **Staged-table notices** from `eurostat_get_dimension_values` name `eurostat_dataframe_describe` before `eurostat_dataframe_query`.

## Fixed

- **`eurostat_browse_themes`** reads a folder row whose last-update column is a single space as having no date.
- **`eurostat_download_dataset`** reports a body that breaks off mid-stream as `upstream_fault` with `retryable: true`, naming the dataset and the decoded bytes read, instead of a reasonless network error.
- **`eurostat_download_dataset`** offers "Retry in a few minutes" beside narrowing when it runs out of time before its first row.
- **Narrowing advice** says "the dimension of" when one dimension is left open.
- **`byte_budget_exceeded`** recovery hint is no longer duplicated.
