# 0.2.0 — 2026-08-04

## Breaking

- **Ten output fields move from required to optional, across three independently declared schemas**, because Eurostat's annotation-derived metadata is no longer fabricated as `0` / `""` when absent — it is omitted. A consumer reading any of these fields unconditionally will break:
  - `eurostat_get_dataset_info` output: `timeRange.start`, `timeRange.end`, `obsCount`, `lastUpdated`.
  - `eurostat://dataset/{dataset_code}` resource output: `timeRange.start`, `timeRange.end`, `obsCount`, `lastUpdated`.
  - `eurostat_query_dataset` output: `timeRange.start`, `timeRange.end`.

  ([#30](https://github.com/cyanheads/eurostat-mcp-server/issues/30), [#33](https://github.com/cyanheads/eurostat-mcp-server/issues/33))

## Changed

- **`eurostat_get_dataset_info` `dimensions[].valuesCount` for `time`** now reflects the dataset's real period count instead of the single-period artifact of the `lastTimePeriod=1` metadata query. Costs one bounded extra upstream request (pinning every other dimension, unfiltered on `time`), and only when the dataset has a `time` dimension. ([#21](https://github.com/cyanheads/eurostat-mcp-server/issues/21))
- **`eurostat_get_dataset_info`'s `async_response` error is no longer `retryable`.** The tool exposes no filters to narrow, so an identical retry produces the identical oversized response. The recovery hint now points to `eurostat_search_datasets`/`eurostat_browse_themes` for catalogue-level coverage or `eurostat_get_dimension_values` for one dimension at a time. ([#31](https://github.com/cyanheads/eurostat-mcp-server/issues/31))
- **`eurostat_query_dataset` `filters` drops zero-length arrays** before building the request, the `geo`/`geo_level` conflict check, and the `appliedFilters` echoed back in both `structuredContent` and `ctx.enrich`. `{"geo": []}` now neither restricts the query nor conflicts with `geo_level`. `appliedFilters` (`Record<string, string[]>`) is added to the tool's output as the filters actually sent upstream. ([#22](https://github.com/cyanheads/eurostat-mcp-server/issues/22))

## Fixed

- **`eurostat_get_dimension_values` rejects `geo_level` paired with any dimension other than `geo`** as a new `conflicting_params` error, instead of silently accepting and ignoring it. ([#25](https://github.com/cyanheads/eurostat-mcp-server/issues/25))
- **Absent Eurostat annotations are omitted rather than fabricated.** `eurostat_get_dataset_info` and the `eurostat://dataset/{dataset_code}` resource no longer default a missing `OBS_COUNT` to `0` or a missing period bound to `""`; `format()` renders each as "not reported by Eurostat" instead of a blank or zero value. ([#30](https://github.com/cyanheads/eurostat-mcp-server/issues/30))
- **`eurostat_query_dataset`'s `timeRange` has the same fabricated-empty-bounds defect fixed**, found during verification of this release: a period bound absent from both the returned observations and the dataset-wide annotations is now omitted rather than reported as `""`. ([#33](https://github.com/cyanheads/eurostat-mcp-server/issues/33))
- **`docs/design.md` and `README.md` corrected** — stale error-code labels (`InvalidParams` → `ValidationError`), the single-request description of `get_dataset_info`, the mutual-exclusion description for `geo`/`geo_level`, and a quoted `async_response` recovery hint that no longer exists.
