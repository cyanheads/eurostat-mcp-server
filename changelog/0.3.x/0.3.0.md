# 0.3.0 — 2026-08-04

## Breaking

- **`dimensions[].valuesCount` and `dimensions[].sampleValues` move from required to optional**, on both `eurostat_get_dataset_info`'s output and the independently declared `eurostat://dataset/{dataset_code}` resource output. They're omitted — not filled from the one-period slice — when the `time` dimension's enumeration follow-up request fails. A consumer reading either field unconditionally will break. ([#34](https://github.com/cyanheads/eurostat-mcp-server/issues/34))

## Fixed

- **`eurostat_get_dataset_info` no longer discards metadata it already retrieved when the follow-up `time`-enumeration request fails.** It now catches that failure and returns everything the primary request produced, with `time`'s `valuesCount`/`sampleValues` omitted — the schema change above. A failure on the primary request still fails the call. This is a regression introduced in 0.2.0: readers on 0.1.x are unaffected; readers on 0.2.0 should upgrade. ([#34](https://github.com/cyanheads/eurostat-mcp-server/issues/34))
- **`eurostat_query_dataset`'s 5,000-row cap now applies during decoding** instead of after the full match has been decoded into observation objects. `obsCount`, `missingObsCount`, and `timeRange` are computed from a separate scan of the response's `value`/`status` cell keys, so they keep describing the whole match regardless of the cap. This removes a million-object intermediate allocation on a broad, unfiltered query — it is not a speed improvement: on the reported case, network transfer is ~93% of the round trip, `JSON.parse` ~1.3%, and decoding ~5%; Eurostat serving the full payload is what dominates, not the decode loop. ([#27](https://github.com/cyanheads/eurostat-mcp-server/issues/27))
- **`eurostat_browse_themes` resolves a folder code filed under more than one TOC branch to its first placement instead of its last.** A new optional `otherPlacements` field on the tool output names the branches not taken, so an ambiguous code is visible as such rather than silently resolved. ([#32](https://github.com/cyanheads/eurostat-mcp-server/issues/32))
