# 0.4.0 — 2026-08-04

## Added

- **`eurostat_dataframe_describe` and `eurostat_dataframe_query`** — SQL access to a dataframe canvas. `describe` lists staged tables with row counts and column types; `query` runs a single read-only `SELECT`, rejecting statement chaining, non-`SELECT` verbs, and functions that read files or external data. Both are registered only when `CANVAS_PROVIDER_TYPE=duckdb`; otherwise they're wrapped in `disabledTool()` — invisible to `tools/list` but still named on the landing page and server card. ([#8](https://github.com/cyanheads/eurostat-mcp-server/issues/8))
- **`eurostat_query_dataset` stages a capped match onto the canvas.** When a match exceeds the 5,000-row inline cap and a canvas is configured, the whole match is written to a SQL table and the response gains `canvasId`, `tableName`, and `stagedRowCount`. Staging is skipped when the result fits inline. Passing a prior response's `canvasId` back as the new optional `canvas_id` input stages the next result onto the same canvas, so two datasets can be joined. ([#8](https://github.com/cyanheads/eurostat-mcp-server/issues/8))
- **Canvas env vars** — `CANVAS_PROVIDER_TYPE`, `CANVAS_TEMP_PATH`, `CANVAS_TTL_MS`, `CANVAS_DEFAULT_ROW_LIMIT`, documented in `.env.example`, `server.json`, and `manifest.json`. Off by default (`none`); the `@duckdb/node-api` binding ships in every install and image, so enabling the canvas needs only the one variable.

## Changed

- **`eurostat_query_dataset`'s row source is a lazy generator** over the response's populated cells, shared by the capped inline decode and the canvas spill. The inline rows are a prefix of the staged table by construction — both walks pull from the same generator — and staging costs no additional request to Eurostat: the full response body is already in memory before decoding starts.
- **Staged columns are flat and declared, not inferred.** Each dimension contributes a `<dim>` code column and a `<dim>_label` column; the observation contributes `obs_value`, `obs_flag`, `obs_flag_label`. The schema is declared up front because DuckDB's inference reads only the leading rows, which would type an all-integer `obs_value` prefix as `BIGINT` and return it as a string.
- **Dockerfile** — the non-root `bun` user now owns `/var/lib/eurostat-mcp-server/canvas-tmp` and `/var/lib/eurostat-mcp-server/canvas-exports`, mapped to `CANVAS_TEMP_PATH` and `CANVAS_EXPORT_PATH`; the prior image had no writable path for either. A canvas-acquire failure caused by an unwritable scratch directory is now re-thrown naming `CANVAS_TEMP_PATH` instead of surfacing a bare `EACCES`.
- **`.mcpb` bundle** — `scripts/clean-mcpb.ts`'s DuckDB-stripping comment updated to describe the binding as a runtime dependency gated on `CANVAS_PROVIDER_TYPE`, not an optional peer. A bundle install still cannot run the canvas — native bindings are stripped from the bundle to keep it portable and under the registry size cap — so SQL analytics needs the npm, Docker, or from-source install.

## Dependencies

- `@duckdb/node-api` `^1.5.5-r.3` added as a runtime dependency (powers the DataCanvas).
