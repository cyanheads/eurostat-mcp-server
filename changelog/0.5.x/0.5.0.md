# 0.5.0 — 2026-08-04

## Added

- **`eurostat_download_dataset`** — downloads a whole dataset through the SDMX 2.1 TSV bulk endpoint (`/sdmx/2.1/data/{dataset}?format=TSV`) instead of the JSON-stat endpoint `eurostat_query_dataset` reads, and stages every observation on the dataframe canvas when one is configured. Filters take the same `{dimension_code: [value, ...]}` map as `eurostat_query_dataset`; the positional SDMX key is built server-side from the dataset's own dimension order, so arity is correct by construction and a filter naming a dimension the dataset does not have is rejected up front with the real dimension list. Narrow with `since_period`/`until_period` — there is deliberately no "last N periods", since the TSV layout keeps a column for every period regardless and `lastNObservations` only blanks the unselected cells. `preview_limit` (default 50, max 500) caps the inline echo; without a canvas only that preview is retained, and the response says so. ([#8](https://github.com/cyanheads/eurostat-mcp-server/issues/8))
- **`EurostatBulkService`** (`src/services/eurostat-bulk/`) — the streaming client behind the new tool: gzip sniffed off the response stream rather than trusted from headers (Eurostat sends no `Content-Encoding` on compressed bodies), a byte budget enforced mid-transfer since the body is `Transfer-Encoding: chunked` with no `Content-Length`, XML SOAP-fault and async-queue-envelope classification, and wide-to-long expansion of the TSV layout into one row per observation.
- **`EUROSTAT_BULK_TIMEOUT_MS`** (default `120000`) and **`EUROSTAT_BULK_MAX_BYTES`** (default `52428800`) — held separate from the existing request timeout because a bulk body streams for minutes where a metadata call answers in seconds.
- **`EurostatDataService.getDimensionOrder`** — resolves a dataset's dimension order (the JSON-stat `id` array minus `time`) from a one-period probe, the input the positional SDMX key is built from.

## Changed

- **`eurostat_query_dataset`, both dataframe tools, `eurostat_get_dataset_info`, `eurostat_get_dimension_values`, and `eurostat_search_datasets` have their descriptions rewritten**, not appended to, to route between a dataset slice (`eurostat_query_dataset`) and a whole dataset (`eurostat_download_dataset`).
- **The two dataframe stagers write different column sets**, and `eurostat_dataframe_describe`/`eurostat_dataframe_query` now say so explicitly: `eurostat_query_dataset` gives each dimension a code column plus a `_label` companion; `eurostat_download_dataset` gives code columns only (the bulk endpoint carries no labels) plus `time`, `conf_status`, and `conf_status_label`. The two tables also disagree on `obs_flag` — JSON-stat folds a confidentiality marker into the observation status, so a confidential cell reads `obs_flag = '|C'` on a query-staged table but `obs_flag = NULL` with `conf_status = 'C'` on a bulk-staged one; join on dimension codes and `time`, not on `obs_flag`.
- **`newTableName()` moved** from `eurostat-query-dataset.tool.ts` to `src/services/canvas-accessor.ts`, so both staging tools share one table-naming helper.
