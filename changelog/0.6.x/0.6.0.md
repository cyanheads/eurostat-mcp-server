# 0.6.0 — 2026-08-04

## Breaking

- **`eurostat_query_dataset`'s `observations[].status` no longer carries a confidentiality code.** JSON-stat publishes no `CONF_STATUS` field and instead folds it into the observation status behind a `|` — a confidential cell arrived as `status: { code: "|C", label: "|confidential" }`. The decoder now splits that separator: `status` carries only the `OBS_FLAG` half and is omitted for a cell with none, while a new sibling field `confStatus: { code, label }` carries the `CONF_STATUS` half, present only when Eurostat restricts the cell. Before: `status.code === "|C"`. After: `status` omitted, `confStatus.code === "C"`. The staged dataframe table gains `conf_status`/`conf_status_label` columns; both `eurostat_query_dataset` and `eurostat_download_dataset` now stage the same five measure columns — `obs_value`, `obs_flag`, `obs_flag_label`, `conf_status`, `conf_status_label` — under the same names with the same codes, so the two join and compare directly instead of disagreeing on what `obs_flag` holds. ([#35](https://github.com/cyanheads/eurostat-mcp-server/issues/35))

## Changed

- **`src/services/eurostat-codelists.ts`** (new) — the `OBS_FLAG`/`CONF_STATUS` code-to-label dictionaries and the five measure column names, previously duplicated between the JSON-stat and SDMX-TSV services, now live in one module both import.
- **`eurostat_query_dataset`, `eurostat_dataframe_describe`, and `eurostat_dataframe_query` descriptions rewritten** to describe the shared measure columns instead of the `obs_flag` divergence the breaking change above removes.

## Fixed

- **`eurostat_query_dataset` no longer rejects a slice whose every cell is confidential as `no_results`.** The guard tested the response's `value` map alone, but the decoder counts a cell as an observation when its index appears in `value` **or** `status` — a wholly-confidential slice carries every cell in `status` with no `value` entry, so it arrived as `value: {}` and was rejected even though the decoder yields it as data. The guard now derives from the same cell count (`obsCount`) the response already reports, so a rejected query and a returned one can no longer disagree about what an observation is. The `no_results` recovery hint also now names the period range, since an out-of-coverage range is the other way Eurostat answers HTTP 200 with nothing. ([#36](https://github.com/cyanheads/eurostat-mcp-server/issues/36))
