# 0.6.5 — 2026-09-21

## Changed

- **`canvas_id`** on `eurostat_query_dataset`, `eurostat_download_dataset`, `eurostat_dataframe_describe`, and `eurostat_dataframe_query` now uses mcp-ts-core's `CanvasIdSchema` (`pattern: ^[A-Za-z0-9_-]{10}$`), so a malformed id is rejected at argument validation with `reason: invalid_arguments` instead of reaching the canvas lookup, or being silently ignored on the two staging tools when nothing is staged. Well-formed ids behave as before.
- **Argument rejections** carry `data.reason: "invalid_arguments"` and a schema-derived `Recovery:` hint (mcp-ts-core 0.13.3).
- **A case-variant argument key** such as `datasetCode` is rewritten to its declared key when it uniquely matches one; any other undeclared key is still rejected (0.13.4).
- **A DuckDB conversion or out-of-range error** in `eurostat_dataframe_query` SQL now comes back as a `ValidationError` with `reason: "sql_execution_error"`, instead of a `DatabaseError` (0.13.4).
- **Tool error text** in `content[]` now closes with `(reason <reason>)`, adding ` · not retryable` where the error contract declares `retryable: false`; `structuredContent` is unchanged (0.13.5).
- **README documents `MCP_SESSION_MODE`** — with it unset the server runs stateless, the default `createApp()` declares; an explicitly set `MCP_SESSION_MODE` still overrides it — and an integration test pins both cases (#43).
- **Repo scaffolding synced** to the current framework template: `.github/workflows/codeql.yml` added, framework skills and `lint-mcp.ts` re-synced, `thrownBy: 'service'` lint markers added to the canvas-lookup error reasons (lint-only metadata; the advertised error contract is unchanged), Dockerfile comments and issue-form text updated.
