# 0.7.0 — 2026-09-25

## Added

- **`invalid_period` on `eurostat_query_dataset` and `eurostat_download_dataset`** ([#47](https://github.com/cyanheads/eurostat-mcp-server/issues/47), [#53](https://github.com/cyanheads/eurostat-mcp-server/issues/53)). `since_period`/`until_period` are checked in the handler before any request: the literal must be an accepted form, every month, quarter, semester, trimester, week, and day it names must exist, and `since_period` must not start after `until_period` ends. Cross-frequency pairs such as `2020-06` to `2020` stay valid.
- **`unmatchedValues` on `eurostat_query_dataset`** ([#52](https://github.com/cyanheads/eurostat-mcp-server/issues/52)) — filter values that matched nothing, keyed by dimension and spelled as sent. `notice` and the text output name them too; omitted when every value matched.
- **`no_results` diagnosis on `eurostat_query_dataset`** ([#48](https://github.com/cyanheads/eurostat-mcp-server/issues/48)) — read from the empty reply with no extra request: `data.unmatchedValues`, and `data.matchedPeriods` (the newest 24 selected periods, none carrying a value) with `data.matchedPeriodCount`. The message and hint name the cause: an unmatched value, a range outside the dataset's coverage (with its oldest and latest period), `last_n_periods` counting back past the slice's latest period, or a combination that carries no data.

## Changed

- **Breaking: `eurostat_download_dataset` enrichment drops `truncated`, `shown`, and `cap`, and adds `totalCount`** ([#49](https://github.com/cyanheads/eurostat-mcp-server/issues/49)), equal to `rowCount`. A preview shorter than the download is disclosed as a `notice` sentence; `budgetExceeded` remains the only signal that the download is incomplete.
- **Breaking: period literals that name a component that does not exist fail as `invalid_period`** instead of reaching Eurostat, which rolled some into a neighbouring period (`2020-13`, `2020-Q5`, `2021-W53`, `2021-02-29`). An inverted range (`since_period` `2024-01` with `until_period` `2020-01`), which Eurostat answered with data outside it, fails the same way.
- **Breaking: period faults move to `invalid_period`** from `conflicting_params` on `eurostat_query_dataset` and from `filter_arity` on `eurostat_download_dataset`. Bulk fault 140 is split on its fault string: `TIME_PERIOD_FILTER_SPEC_INVALID` maps to `invalid_period`, `INVALID_QUERY_NB_FILTERS` stays `filter_arity`.
- **Breaking: an upper-case filter key with `geo_level` fails as `conflicting_params`** ([#54](https://github.com/cyanheads/eurostat-mcp-server/issues/54)); `GEO` previously bypassed the check.
- **Filter keys match dimension codes in any case** on both data tools ([#54](https://github.com/cyanheads/eurostat-mcp-server/issues/54)). `eurostat_download_dataset` places `GEO` at `geo` instead of rejecting it, and keys that differ only in case pool their values.
- **Period literals are sent in canonical form** and echoed that way in `appliedFilters`/`appliedQuery`: extra leading zeros after the letter are dropped (`2020-Q01` → `2020-Q1`), a day of the year is sent as three digits (`2026-D1` → `2026-D001`), and `YYYY-A1` is sent as `YYYY`.
- **`eurostat_dataframe_describe` and `eurostat_dataframe_query` recovery hints** name both staging tools for an unknown or expired canvas or table.
- **Tool descriptions and docs**: `last_n_periods` states it counts back from the dataset's latest period, not the slice's; `eurostat_get_dimension_values` states an invalid code is named as unmatched; the README capability reference and configuration table are rewritten to match current behavior.

## Fixed

- **`eurostat_download_dataset`'s no-canvas notice** ([#49](https://github.com/cyanheads/eurostat-mcp-server/issues/49)) no longer recommends a narrower query when every row came back inline, and names the `preview_limit` that returns them all when the download holds 500 rows or fewer.
- **`eurostat_download_dataset`'s `no_results` hint** also names a `since_period`/`until_period` range that misses the filtered series.
